# Intake index

Requirements this website places on content supplied by product domains (app
repositories, their agents, or the owner). Used by the `domain-collaboration`
skill.

This index **points to sources; it does not copy values.** Always read the
linked source for current values. If a link is broken, stop and run an intake
refresh.

- Status: **approved**. Generated by an intake scan on 2026-11-02; its
  summaries are provisional, but existing requirements in the linked sources
  remain in force.
- Approved on: 2026-11-02
- Approved by: repository owner
- Scope: product catalog records, screenshots, icons and social cards, marketing
  copy, distribution facts, and app privacy, support and accessibility policies.

## How to use

1. Find the categories your exchange's scope touches.
2. Read every linked source and derive concrete acceptance criteria.
3. Cite the source for each criterion in your REQUEST.

Enforcement levels: **enforced** means code or tests reject violations,
**documented** means a written rule only, and **inferred** means a pattern seen
only in existing content.

## Approvals and gates

An exchange does not override owner-only gates or existing authorizations:

- Policy text and publication facts: [privacy gates](privacy.md),
  [policy publication](../src/content/policy-publication.json). Use the existing
  authorization for actual creation/change dates in [AGENTS.md](../AGENTS.md).
- Analytics behavior or disclosure changes invalidate the analytics approval:
  [analytics](analytics.md).
- Commit, push, merge, deploy and DNS rules: [AGENTS.md](../AGENTS.md),
  [deployment](deployment.md).

## Known limitations

These were found during the scan. They are not resolved here.

- Utility presentation, icon variants and DMG distribution are currently
  specific to Override in the [catalog schema](../src/lib/catalog.ts). A
  second utility or direct-download app needs schema work first.
- The [media pipeline](../scripts/prepare-media.mjs) hard-codes Feelory's
  screenshot list and source path. Screenshots for another app need their own
  pipeline support.
- Existing Feelory captures have light and dark coverage, but the schema makes
  the dark variant optional. Do not treat paired coverage as a requirement for
  every product without an owner decision.
